# 6. 前端架构 — 交互层

> 本层只回答一件事：**用户操作之后发生什么**。不涉及代码组织方式（第 5 节）与视觉表现（第 7 节）。
> 结构：每个模块按 **状态 → 事件 → 反馈 → 边界情况** 四段式描述。

---

## 6.1 交互设计原则

| 原则 | 具体含义 | 反面案例 |
|---|---|---|
| **立即反馈** | 100ms 内必须有视觉响应，即使数据未到 | 点击上传后按钮毫无变化，用户重复点击 |
| **乐观 vs 保守** | 低风险高频率操作乐观更新；高风险操作等服务端确认 | 审核"通过"乐观显示成功，实际服务端失败 |
| **可撤销** | 破坏性操作给撤销窗口，而非弹窗二次确认 | 每次删除都弹"确定吗"，用户形成肌肉记忆后盲点 |
| **渐进披露** | 高级选项默认折叠，不干扰主流程 | 上传页首屏铺满 20 个参数 |
| **状态可见** | 长任务显示进度与预估时间，而非不确定的转圈 | 转码 10 分钟只有一个 spinner |
| **错误可恢复** | 错误提示必须附带下一步动作 | "上传失败"（然后呢？） |
| **键盘可达** | 所有核心操作有快捷键，审核工作台尤其重要 | 审核员每天用鼠标点 500 次 |

## 6.2 视频播放器交互

### 6.2.1 状态模型

```
播放器状态机
├── IDLE           初始，未加载
├── LOADING        正在获取播放凭证 + 初始化内核
├── READY          清单已加载，等待播放指令
├── PLAYING        ▶ 播放中
├── PAUSED         ⏸ 暂停
├── BUFFERING      ⟳ 缓冲（网络波动或码率切换）
├── SEEKING        ⟳ 拖动中
├── ENDED          播放结束
└── ERROR          不可恢复错误（鉴权失效/源不可用）
```

**状态与 UI 映射**（详细视觉规则见第 7 节）：

| 状态 | 控件行为 | 提示 |
|---|---|---|
| LOADING | 控件禁用，显示骨架 | 无文字 |
| PLAYING | 控件 3 秒后淡出，鼠标移动/触摸唤出 | 无 |
| BUFFERING | 控件保持可见 | 转圈叠加在画面中央 |
| SEEKING | 显示时间预览气泡 | `12:34 / 1:30:20` |
| ENDED | 显示重播按钮 + 推荐列表 | — |
| ERROR | 显示错误卡片，含重试按钮 | 见 6.2.6 |

### 6.2.2 主流程：进入播放页

```
用户点击内容卡片
  ↓
路由跳转 /v/:contentId
  ↓
① 并发发起两个请求
   ├─ GET /contents/:id          → 内容元信息（标题、简介、统计）
   └─ GET /contents/:id/playback → 播放凭证（签名 URL、清晰度列表）
  ↓
② 元信息先返回 → 立即渲染标题、简介、评论区骨架屏
   （不等播放凭证，避免整页白屏）
  ↓
③ 播放凭证返回 → 动态 import 播放器内核（仅首次加载此 chunk）
  ↓
④ 内核初始化 → 传入 manifestUrl → READY
  ↓
⑤ 依据用户偏好自动决策
   ├─ resumePositionMs > 30s 且 < 时长-30s → 显示"继续观看"气泡，5 秒后自动消失
   └─ 否则从 0 开始
  ↓
⑥ 自动播放策略检查
   ├─ 用户此前有交互（页面内点击过）→ 尝试 play()
   └─ 无交互 → 静音 + 自动播放；显示"点击取消静音"提示
   （浏览器 autoplay 策略要求：有声自动播放必须建立在用户手势之上）
```

**关键决策：内容元信息与播放凭证并发请求，而非串行。** 元信息通常命中缓存（50ms），播放凭证需服务端查库 + 签名（150ms）。串行会让用户多等 150ms。

### 6.2.3 自适应码率切换

```
内核每 3 秒采集网络指标（下载速率、缓冲区余量、丢帧率）
  ↓
决策逻辑
  ├─ 缓冲区 < 5s 且 带宽持续低于当前档位 → 降档
  ├─ 缓冲区 > 20s 且 带宽高于上一档位 30% 持续 10s → 升档
  └─ 否则保持当前档位（避免频繁抖动）
  ↓
切换时
  ├─ 用户无感知：在当前分片播完后无缝切到新码率
  ├─ 不中断播放、不重置进度
  └─ 顶部短暂提示"已切换到 720p"（2 秒自动消失）
```

**用户手动指定清晰度时**：关闭自动切换，直到用户重新选择"自动"。若指定档位因网络无法维持，显示"网络较慢，建议切换"但**不强制切换**——尊重用户选择。

### 6.2.4 交互事件清单

| 事件 | 触发 | 响应 | 边界处理 |
|---|---|---|---|
| 单击画面 | 鼠标点击 | 播放/暂停切换 | 双击区域除外（防误触） |
| 双击画面 | 快速两次点击 | 全屏切换 | 300ms 内判定，与单击互斥 |
| 双击左/右 1/3 | 双击热区 | 后退/前进 10 秒 | 显示 `-10s` 涟漪动画 |
| 空格 | 键盘 | 播放/暂停 | 焦点在输入框时不拦截 |
| ← / → | 键盘 | ±5 秒 | Shift + 方向键 = ±30 秒 |
| ↑ / ↓ | 键盘 | 音量 ±5% | 到 0 自动静音 |
| M | 键盘 | 静音切换 | — |
| F | 键盘 | 全屏切换 | — |
| C | 键盘 | 字幕开关 | — |
| D | 键盘 | 弹幕开关 | — |
| 0–9 | 键盘 | 跳转到 0%–90% | — |
| `,` / `.` | 键盘 | 减速/加速（0.25 步进） | 范围 0.25x–3x |
| ESC | 键盘 | 退出全屏 / 关闭浮层 | 优先级：浮层 > 全屏 |
| 拖动进度条 | 鼠标 / 触摸 | 预览缩略图 + 时间 | 松手才真正 seek |
| 滚轮 | 鼠标 | 音量调节（悬停播放器时） | 需按住 Ctrl 才拦截页面滚动 |

**进度条拖动细节**：
```
按下 → SEEKING 状态，暂停进度更新，显示拖动手柄
     → 依据横坐标计算目标时间
     → 从精灵图（sprite）截取对应帧作为预览
     → 异步节流显示预览气泡（每 100ms 更新一次，避免过度渲染）
松开 → 执行 seek
     → 若目标与当前位置差 > 2s，显示短暂 loading
     → 更新播放进度上报
```

**为什么松手才 seek**：边拖边 seek 会产生大量 HTTP Range 请求，且 HLS 分片边界导致画面跳动，体验反而更差。

### 6.2.5 倍速播放

```
可选档位：0.25 / 0.5 / 0.75 / 1.0 / 1.25 / 1.5 / 1.75 / 2.0 / 2.5 / 3.0
  ↓
切换时
  ├─ 保持音频音调（preservesPitch = true），避免"花栗鼠"效应
  ├─ 弹幕时间轴同步缩放（视频时间基准不变，弹幕按 videoTimeMs 定位，无需特殊处理）
  └─ 偏好持久化到 localStorage，下次自动应用
  ↓
超过 2.0x 时
  └─ 顶部提示"高倍速下字幕可能不同步"（仅提示一次，不阻断）
```

### 6.2.6 错误处理矩阵

| 错误 | 判定 | 用户可见反馈 | 可执行动作 |
|---|---|---|---|
| 凭证过期（403） | `code: PLAYBACK_NOT_PERMITTED` | "播放凭证已过期" | 自动静默重新获取凭证并续播（保留进度） |
| 并发流超限（429） | `TOO_MANY_CONCURRENT_STREAMS` | "同时在多个设备播放" | "在此设备继续"按钮 → 踢掉其他会话 |
| 内容被拦截（403） | `CONTENT_BLOCKED` | "内容因违规被限制" | "申诉"按钮（仅上传者可见） |
| 网络中断 | `navigator.onLine === false` | "网络已断开" | 监听 online 事件自动续播 |
| 分片加载失败 | 内核 error 事件 | 内联重试，最多 3 次指数退避 | 3 次后显示"播放出错"+ 重试按钮 |
| 格式不支持 | 内核 `MEDIA_ERR_SRC_NOT_SUPPORTED` | "浏览器不支持此格式" | "下载播放"或"切换清晰度" |
| 解码错误 | `MEDIA_ERR_DECODE` | "解码失败" | 建议降低清晰度（可能是硬件不支持） |

**续播的关键实现**：
```
捕获 403 → 暂停 → 记录 currentTime
       → 调用 GET /contents/:id/playback 重新获取签名 URL
       → 替换内核 source → seek 回记录的时间点 → play()
       → 整个过程不打断用户，仅显示 1 秒的"正在刷新凭证"
```

### 6.2.7 弹幕叠加层交互

| 交互 | 行为 |
|---|---|
| 发送 | 输入框回车或点击发送 → 乐观插入（立刻出现在轨道上）→ 服务端返回后替换临时 ID |
| 命中敏感词 | 服务端 `422` → 回滚乐观插入 → 输入框保留文本并标红 → 提示"包含违规内容" |
| 悬停弹幕 | 暂停该条弹幕移动（不暂停视频），显示操作菜单 |
| 点击弹幕 | 显示"举报 / 屏蔽该用户 / 复制"菜单 |
| 屏蔽用户 | 本地黑名单（localStorage），该用户弹幕不再渲染 |
| 密度控制 | 同屏最多 N 条（默认 80），超出则丢弃低优先级弹幕 |
| 轨道分配 | 每条弹幕分配到最早可用的轨道；全满则丢弃（不堆叠重叠） |
| 时间窗加载 | 只请求 `[currentTime - 30s, currentTime + 60s]` 区间，滚动式预取 |
| 拖动跳转 | 清空当前轨道，按新位置重新请求时间窗 |

**弹幕与倍速的协同**：
```
弹幕位置 = (videoTimeMs - currentTimeMs) * 1000 / playbackRate  ← 像素换算需除以倍速
```
若不除以倍速，2 倍速下弹幕会以两倍速度飞过屏幕，与内容脱节。

**弹幕与暂停**：暂停时弹幕**全部冻结**（包括 CSS 动画），恢复时继续。实现上用 `animation-play-state: paused` 而非重新计算位置。

## 6.3 音频播放器交互

### 6.3.1 后台持续播放

这是音频模块的核心难点。默认情况下，SPA 路由切换会卸载组件、停止音频。

```
方案：把音频内核实例提升到 app 层（全局单例），而非页面组件内
  ↓
① 内核生命周期与应用一致，路由切换不销毁
② 页面组件只订阅内核状态并渲染控件
③ 路由切换时
   ├─ 同内容 → 无缝继续（无感知）
   ├─ 新内容 → 内核换源，显示迷你播放条
   └─ 离开音频页 → 底部/角落显示迷你播放器，可继续控制
  ↓
④ 页面刷新 → 音频必然中断（浏览器限制）
   └─ 持久化 lastPlayedContentId + positionMs
   └─ 下次进入时提示"继续播放上次内容"
```

**Media Session API 集成**（锁屏/系统媒体控制）：

```typescript
navigator.mediaSession.metadata = new MediaMetadata({
  title: content.title,
  artist: content.uploader.displayName,
  album: content.category?.name,
  artwork: [
    { src: thumb480, sizes: '480x480', type: 'image/jpeg' },
    { src: thumb96,  sizes: '96x96',   type: 'image/jpeg' },
  ],
});

navigator.mediaSession.setActionHandler('play',          () => player.play());
navigator.mediaSession.setActionHandler('pause',         () => player.pause());
navigator.mediaSession.setActionHandler('previoustrack', () => playPrevious());
navigator.mediaSession.setActionHandler('nexttrack',     () => playNext());
navigator.mediaSession.setActionHandler('seekbackward',  (d) => player.seek(-(d.seekOffset ?? 10)));
navigator.mediaSession.setActionHandler('seekforward',   (d) => player.seek(d.seekOffset ?? 10));
navigator.mediaSession.setActionHandler('seekto',        (d) => player.seekTo(d.seekTime));
```
这让用户在锁屏、蓝牙耳机、车机上都能控制播放——移动端体验的关键。

### 6.3.2 可视化频谱

```
音频源 → Web Audio API AnalyserNode → requestAnimationFrame 绘制
  ↓
关键约束：不能直接连接 <audio> 元素（会破坏后台播放）
  ↓
正确做法
  ├─ 创建 AudioContext
  ├─ createMediaElementSource(audioElement)  → 接入分析链
  ├─ 分析节点旁路连接到 destination（保证仍有声音）
  └─ 页面隐藏 / 音频暂停时 → 停止 rAF 循环（省电，频谱静止）
  ↓
性能控制
  ├─ fftSize = 2048（平衡分辨率与开销）
  ├─ 优先 Web Worker + OffscreenCanvas 绘制
  └─ 降级：不支持时用 Canvas 主线程绘制，或隐藏可视化
  ↓
无障碍
  └─ 可视化标记 aria-hidden="true"（纯装饰，屏幕阅读器应忽略）
  └─ 若提供"频谱"作为功能，则需替代文本描述
```

### 6.3.3 音频交互事件

| 事件 | 响应 | 边界 |
|---|---|---|
| 播放/暂停 | 切换 | 空格快捷键 |
| ← / → | ±5 秒 | Shift 组合 = ±30 秒 |
| ↑ / ↓ | 音量 ±5% | M 静音 |
| 点击进度条 | 跳转 | 与视频一致，松手才 seek |
| 循环模式 | 单曲 / 列表 / 随机 | 图标四态切换 |
| 播放列表项点击 | 切歌 | 保留当前音量与倍速设置 |
| 可视化开关 | 显示/隐藏频谱 | 低端设备默认关闭 |
| 后台标签页 | 继续播放 | 页面隐藏时暂停 rAF，但**不暂停音频** |

## 6.4 文本阅读器交互

### 6.4.1 沉浸式阅读模式

```
进入阅读页
  ↓
默认标准模式（保留站点导航、侧边目录）
  ↓
用户点击"沉浸式"按钮 或 按 F11 风格的快捷键
  ↓
切换逻辑
  ├─ 路由跳转 /immersive/read/:contentId（使用 ImmersiveLayout）
  │   （用路由而非 CSS 隐藏导航——刷新后状态保持，且可分享链接）
  ├─ 隐藏导航、侧边栏、页脚、评论
  ├─ 正文区域扩展到最佳阅读宽度（详见第 7 节）
  ├─ 保存滚动位置 → 切换后精确恢复
  └─ 进入时显示 2 秒后自动隐藏的退出提示
  ↓
退出沉浸式
  ├─ 按 ESC
  ├─ 滚动到顶部/底部时向下/上继续滚动
  └─ 点击右上角退出按钮（悬停顶部区域时出现）
```

**关键细节：滚动位置保持。** 沉浸式切换会改变布局宽度，导致内容重排。必须记录**锚点元素**（当前视口顶部的段落），而非像素偏移：

```
切换前：记录当前视口顶部最近的 [data-anchor] 元素及其 id
切换后：布局稳定 → scrollIntoView 该锚点 → 视觉上内容位置不变
```

若只记 `scrollTop` 像素值，宽度变化后用户会跳到完全不同的段落。

### 6.4.2 阅读偏好自定义

| 偏好 | 选项 | 生效范围 | 持久化 |
|---|---|---|---|
| 字号 | 14 / 16 / 18 / 20 / 22 / 24 px | 正文 | localStorage + 服务端同步 |
| 行距 | 1.4 / 1.6 / 1.8 / 2.0 / 2.4 | 正文 | 同上 |
| 段间距 | 紧凑 / 标准 / 宽松 | 正文 | 同上 |
| 字体 | 系统 / 衬线 / 无衬线 | 正文 | 同上 |
| 内容宽度 | 窄(60ch) / 标准(72ch) / 宽(88ch) | 正文容器 | 同上 |
| 主题 | 浅色 / 深色 / 护眼(米黄) / 跟随系统 | 全局 | 同上 |
| 对齐 | 左对齐 / 两端对齐 | 正文 | 同上 |
| 首行缩进 | 开 / 关 | 中文段落 | 同上 |

**交互形态**：偏好面板从侧边滑出，调整**立即生效**（预览式，无需确认按钮）。面板打开时正文仍可见，用户能实时看到效果。

**服务端同步策略**：
```
本地修改 → 立即写 localStorage（同步，零延迟）
        → 防抖 1000ms → PATCH /me { readingPreferences }
        → 失败则静默保留本地值，下次登录时以服务端为准
```
这样离线/未登录也能用，登录后跨设备同步。

### 6.4.3 阅读进度与导航

| 功能 | 交互 |
|---|---|
| 进度显示 | 顶部细进度条 + 右下角百分比圆环 |
| 目录跳转 | 点击章节 → 平滑滚动 → URL 更新锚点（可分享、可前进后退） |
| 键盘翻页 | PageDown / PageUp 翻一屏；J / K 同效（Vim 风格） |
| 章节切换 | `[` 上一章 / `]` 下一章 |
| 阅读位置记忆 | 每 5 秒或滚动停止时上报 `POST /contents/:id/progress` |
| 恢复位置 | 再次进入时提示"上次读到 62%，继续？"，3 秒后自动跳转 |
| 当前章节高亮 | 目录中高亮当前视口所在章节（IntersectionObserver） |

### 6.4.4 富文本渲染的安全交互

富文本来自用户上传，**渲染前必须净化**：

```
渲染管道
  ↓
① 服务端已做一次净化（保存时）
② 客户端二次净化（DOMPurify，防止服务端被绕过的漏网）
  ↓
③ 白名单标签：p, h1-h6, strong, em, u, s, blockquote,
             ul, ol, li, a, img, code, pre, table, hr, br
④ 白名单属性：href, src, alt, title, colspan, rowspan
⑤ 强制处理
   ├─ <a> 加 rel="noopener noreferrer nofollow" + target="_blank"
   ├─ <img> 加 loading="lazy" + 限制 max-width
   ├─ 剥离所有 on* 事件属性
   ├─ 剥离 javascript: / data: 协议（除合法图片 data URI）
   └─ 剥离 <script> <iframe> <object> <embed> <form>
  ↓
⑥ 外链点击拦截
   └─ 站外链接显示跳转确认："即将离开本站，前往 example.com"
```

**图片交互**：点击放大（Lightbox）→ ESC 或点击背景关闭 → 支持左右切换同篇内图片 → 支持双指/滚轮缩放。

## 6.5 上传交互

### 6.5.1 完整上传流程（用户视角）

```
① 拖拽文件到区域 或 点击选择
  ↓
② 客户端预检（不发请求，立即反馈）
   ├─ 扩展名白名单 → 不在列表 → 标红"不支持的格式"
   ├─ 文件大小 vs 用户配额 → 超出 → 标红"超出单文件上限 2GB"
   ├─ 当日配额余量 → 不足 → 标黄"今日配额剩余 1 次，本文件不占用"
   └─ 通过 → 加入待上传列表
  ↓
③ 计算 SHA-256（Web Crypto API，Worker 中计算不阻塞 UI）
   └─ 大文件进度显示"正在校验文件完整性 43%"
   └─ 超时或用户跳过 → 仍可上传（sha256 为可选项）
  ↓
④ 申请上传凭证  POST /contents/upload-intent
   ├─ 服务端返回 429 配额超限 → 显示配额详情 + 重置时间
   ├─ 服务端返回 413 文件过大 → 明确提示上限
   └─ 成功 → 拿到 presignedUrl + contentId
  ↓
⑤ 直传对象存储（XHR，非 fetch —— 需要上传进度事件）
   ├─ 实时进度条（已上传 / 总大小 + 速率 + 剩余时间）
   ├─ 支持暂停 / 继续（利用 XHR abort + 重新申请凭证续传）
   └─ 网络中断 → 自动重试 3 次 → 仍失败则保留在列表可手动重试
  ↓
⑥ 回调  POST /contents/:id/upload-complete
   ├─ 400 FORMAT_MISMATCH → "文件内容与扩展名不符，已拒绝"
   └─ 200 → 状态变为"处理中"
  ↓
⑦ 异步处理阶段（轮询或 WebSocket 推送）
   ├─ 转码中 → 进度条 → "正在转码，预计 3 分钟"
   ├─ 预审中 → 状态文字
   ├─ 预审通过（低风险）→ "已发布" + 跳转内容页按钮
   ├─ 进入人工复审 → "审核中，预计 2 小时" + 说明这是正常流程
   └─ 被拦截 → "未通过审核" + 原因摘要 + "申诉"按钮
```

### 6.5.2 批量上传（特权用户）

| 差异点 | 普通用户 | 特权用户（`content:upload_batch`） |
|---|---|---|
| 单次文件数 | 1 | 最多 50 |
| 并发上传数 | 1 | 3（可配置，避免打满带宽） |
| 配额提示 | 显示剩余配额条 | 不显示（无限制），但显示"不限配额"标识 |
| 批量元数据编辑 | 无 | 支持选中多个 → 统一设置分类/标签 |
| 失败重试 | 单个重试 | "重试全部失败项" |
| 队列持久化 | 否 | 是（刷新页面后队列保留，localStorage） |

**并发上传的调度**：
```
队列 [f1, f2, f3, f4, f5]，并发上限 3
  ↓
t0: f1 f2 f3 同时开始
t1: f1 完成 → f4 开始
t2: f2 完成 → f5 开始
  ↓
完成顺序不保证，列表中按加入顺序排列，不因完成顺序跳动（避免视觉混乱）
```

### 6.5.3 上传状态与重试矩阵

| 状态 | 图标 | 可执行操作 | 自动重试 |
|---|---|---|---|
| 待上传 | ○ | 移除 | — |
| 校验中 | ⟳ + 百分比 | 取消校验 | — |
| 上传中 | ⟳ + 进度 | 暂停 / 取消 | 网络错误自动重试 3 次 |
| 已暂停 | ‖ | 继续 / 移除 | — |
| 服务端校验中 | ⟳ | 等待 | — |
| 转码中 | ⟳ + 预估 | 等待（可离开页面） | — |
| 审核中 | ⏳ | 等待 | — |
| 已发布 | ✓ | 查看 / 复制链接 | — |
| 已拦截 | ⚠ | 申诉 / 删除 | — |
| 失败 | ✗ | 重试 / 移除 | 不自动（需用户决策） |

**为什么失败不自动重试**：格式错误、配额超限等失败重试必然再失败。只有网络类错误才自动重试。

### 6.5.4 断点续传交互

```
大文件上传中断后
  ↓
显示"上传中断，已上传 1.2GB / 2.0GB"
  ↓
点击继续
  ├─ 若凭证未过期（15 分钟内）→ 直接继续
  └─ 已过期 → 重新申请凭证
       ├─ 对象存储支持分片上传（Multipart Upload）
       │   └─ 列出已上传分片 → 从断点继续 → 节省重新传输
       └─ 不支持 → 从头开始（明确提示用户）
```

**技术前提**：需要服务端支持 Multipart Upload 的 presigned URL 签发（每个分片独立签名），且上传意图需记录 `uploadId`。这一点在设计上传 API 时需预留——若初期不做，中断即重传，大文件体验差。

## 6.6 审核工作台交互

审核工作台是管理员使用强度最高的界面，**交互效率直接决定审核吞吐量**。

### 6.6.1 工作台布局与核心循环

```
┌──────────────┬────────────────────────────┬──────────────┐
│  队列列表     │      内容预览区             │  决策面板     │
│  (可折叠)     │                            │              │
│              │  ┌──────────────────────┐  │  风险评分     │
│ ▸ 高风险 12  │  │                      │  │  ████████░░ 82│
│ ▸ 中风险 130 │  │   视频预览 / 阅读预览  │  │              │
│              │  │   （低码率+水印）      │  │  命中详情     │
│ ┌──────────┐ │  │                      │  │  · 关键词 @08:05│
│ │内容A  82 │ │  └──────────────────────┘  │  · 画面 @12:30│
│ │内容B  78 │ │                            │              │
│ │内容C  75 │ │  时间轴标注（可点击跳转）   │  ┌──────────┐│
│ └──────────┘ │                            │  │ ✓ 通过   ││
│              │                            │  │ ✗ 驳回   ││
│              │                            │  │ 🚫 封禁  ││
│              │                            │  └──────────┘│
└──────────────┴────────────────────────────┴──────────────┘
```

### 6.6.2 效率优化交互

| 功能 | 实现 | 收益 |
|---|---|---|
| **键盘全流程** | 见 6.6.3 | 审核员不碰鼠标，吞吐量提升 2–3 倍 |
| **自动领取下一个** | 决策提交后自动加载队列下一条 | 消除"返回列表→点击下一条"的往返 |
| **预加载下一条** | 当前条审核时后台预取队列下一条 | 切换无等待 |
| **命中时间点直达** | 点击命中项 → 播放器 seek 到 `timeMs` ± 5 秒 | 无需手动查找违规片段 |
| **上下文保留** | 记住上次的驳回理由，作为默认值 | 同类违规批量处理更快 |
| **风险分排序** | 默认高风险优先 | 严重内容优先处置 |
| **批量操作** | 勾选多条 → 批量通过（仅限同类型低风险） | 处理大量明显合规内容 |
| **标注反馈** | 决策时可勾选"AI 误判" | 反馈回流，改进模型 |

**批量操作的安全约束**：批量**通过**允许（低风险内容笔误代价小），批量**驳回**禁止——驳回会通知用户并可能影响账号，必须逐条确认理由。

### 6.6.3 键盘快捷键（审核工作台）

| 键 | 动作 | 说明 |
|---|---|---|
| `J` / `↓` | 下一条 | Vim 风格，列表导航 |
| `K` / `↑` | 上一条 | — |
| `空格` | 播放/暂停预览 | 与视频播放器一致 |
| `←` / `→` | 预览 ±5 秒 | — |
| `1`–`9` | 跳转到第 N 个命中时间点 | 快速定位违规片段 |
| `A` | **通过** | Approve，需二次确认可关闭 |
| `R` | **驳回** | Reject，打开理由输入框 |
| `B` | **封禁上传者** | Ban，需 `user:ban` 权限 + 二次确认 |
| `F` | 标记 AI 误判 | 反馈回流 |
| `S` | 保存草稿（暂不决策） | 需要更多信息时 |
| `?` | 显示快捷键帮助 | — |
| `ESC` | 关闭浮层 / 取消当前操作 | — |

**防误操作设计**：
- `A`（通过）默认**不需要**二次确认，但提供开关，高风险内容（`riskLevel >= HIGH`）强制确认
- `R`（驳回）必须输入理由才能提交，理由最少 10 字符
- `B`（封禁）必须二次确认，且显示将被隐藏的内容数量

### 6.6.4 任务领取与并发

```
审核员打开工作台
  ↓
GET /admin/audit/queue → 返回队列（含 queueStats）
  ↓
点击某条 → POST /admin/audit/:id/claim
  ├─ 200 → 进入审核状态，该条对其他人显示"审核中 by mod_alice"
  ├─ 409 ALREADY_CLAIMED → 提示"该内容已被他人领取"→ 自动刷新队列
  └─ 领取后 15 分钟未决策 → 自动释放回队列（防止占用）
  ↓
提交决策 → POST /admin/audit/:id/decision
  ├─ 200 → 显示"已处理" toast → 自动加载下一条（预取的）
  └─ 409 → 状态已变更 → 刷新队列，提示"内容状态已变化"
```

**乐观锁的实际体验**：审核员 A 和 B 同时点开同一条，A 先提交成功；B 提交时收到 409，界面提示"该内容已被 mod_alice 处理"，并显示 A 的决策结果——**不让 B 白做一轮判断**。

### 6.6.5 高风险内容的额外确认

```
判定：riskLevel === 'CRITICAL' 或 存在 severity === 'BLOCK' 的命中
  ↓
决策面板显示额外区块
  ├─ 完整命中详情（而非摘要）
  ├─ 原始 AI 引擎置信度
  ├─ 该上传者的历史违规记录（近 90 天）
  └─ "通过"按钮需二次确认
  ↓
二次确认弹窗内容
  "此内容被 AI 标记为高风险（评分 95）。
   通过后将对全站用户可见。
   确认通过？"
  [取消]  [确认通过]
```

## 6.7 申诉交互

### 6.7.1 用户侧申诉流程

```
用户收到"内容被拦截"通知
  ↓
点击通知 → 进入申诉页 /appeals/new?contentId=xxx
  ↓
页面展示
  ├─ 被拦截的内容摘要（标题、缩略图）
  ├─ 拦截原因摘要（**不暴露完整规则**，防止被针对性规避）
  │   · 好："可能包含不当画面"
  │   · 坏："命中 NSFW 规则 RULE-1042，置信度 0.87，位于 08:05"
  ├─ 申诉截止时间（30 天倒计时）
  └─ 申诉表单
  ↓
表单填写
  ├─ 申诉理由（必填，最少 20 字符）
  ├─ 补充材料上传（可选，最多 5 个文件，每个 ≤ 10MB）
  └─ 联系方式（可选）
  ↓
提交 → POST /appeals
  ├─ 409 APPEAL_ALREADY_OPEN → 显示已有申诉的进度
  ├─ 429 频率超限 → 提示"每日最多提交 3 次申诉"
  └─ 201 → 显示"已提交，预计 24 小时内处理"
  ↓
申诉状态页
  └─ 时间线：已提交 → 审核中 → 已通过/已驳回
  └─ 通过 → 内容自动恢复 + 通知
  └─ 驳回 → 显示审核说明；该次申诉关闭
       └─ 允许就**新的理由或新证据**再次申诉（受同一内容"同时仅一个未结申诉"
          与每日 3 次的总量限制约束），但不得以完全相同的理由重复提交
       └─ 若已超过 30 天申诉窗口 → 提交入口替换为人工客服通道
```

### 6.7.2 审核员侧申诉处理

| 交互 | 说明 |
|---|---|
| 独立队列 | 申诉队列优先级高于新内容审核（用户已在等待） |
| 回避校验 | 前端先校验：若当前审核员是原驳回者，禁用决策按钮并提示（服务端仍会二次校验） |
| 材料查看 | 内嵌查看申诉材料（PDF 预览、图片查看、文本内容） |
| 原决策对照 | 并排显示原审核理由与用户申诉理由 |
| 决策 | 通过 → 内容恢复；驳回 → 必须填写说明（用户可见） |

## 6.8 全局交互模式

### 6.8.1 网络状态处理

| 场景 | 交互 |
|---|---|
| 离线 | 顶部常驻条"当前处于离线状态"，操作按钮禁用并说明原因 |
| 恢复在线 | 自动重新拉取失效的查询（TanStack Query `refetchOnReconnect`） |
| 请求超时 | 显示"请求超时，正在重试 (1/2)"，而非立即报错 |
| 慢网络 | 超过 3 秒显示"网络较慢，请稍候"，超过 10 秒提供取消按钮 |

### 6.8.2 加载状态的分级

| 预期耗时 | 表现 |
|---|---|
| < 200ms | 不显示任何 loading（避免闪烁） |
| 200ms – 1s | 骨架屏（保留布局结构） |
| 1s – 3s | 骨架屏 + 延迟说明文字 |
| > 3s | 进度指示 + 预估时间 + 取消入口 |

**骨架屏优于 spinner**：骨架屏保留布局尺寸，内容到达时无布局跳动（CLS 更低）。spinner 是"我不知道会加载出什么"的懒惰答案。

### 6.8.3 通知与提示

| 类型 | 位置 | 自动消失 | 用途 |
|---|---|---|---|
| 成功 toast | 右上角 | 3 秒 | 操作完成 |
| 错误 toast | 右上角 | 不自动（需手动关） | 操作失败，附重试入口 |
| 警告条 | 页面顶部常驻 | 否 | 配额不足、账号受限 |
| 确认弹窗 | 居中 | 否 | 破坏性操作 |
| 内联错误 | 表单字段下方 | 否 | 校验失败 |
| 进度通知 | 右下角浮层 | 完成后 5 秒 | 转码、导出等长任务 |

**撤销优于确认**：删除内容后显示"已删除 [撤销]"，撤销窗口 8 秒。8 秒内点击则恢复。这比"确定要删除吗"弹窗体验好得多，且同样安全。

### 6.8.4 无障碍交互

| 项 | 要求 |
|---|---|
| 键盘可达 | 全部交互元素可 Tab 到达，焦点顺序符合视觉顺序 |
| 焦点管理 | 打开弹窗 → 焦点移入弹窗并锁定；关闭 → 焦点返回触发元素 |
| 屏幕阅读器 | 动态内容用 `aria-live` 播报（如"已通过审核"） |
| 播放器控件 | 每个按钮有 `aria-label`，进度条用 `role="slider"` + `aria-valuenow` |
| 弹幕 | 提供开关（默认开启但可关闭）；关闭后不渲染，减少认知负担 |
| 降低动效 | 尊重 `prefers-reduced-motion`，关闭弹幕动画、过渡效果 |
| 字幕 | 视频默认提供字幕开关；无字幕时明确标注 |

### 6.8.5 移动端交互差异

| 功能 | 桌面 | 移动端 |
|---|---|---|
| 播放器控件 | 悬停显示 | 点击显示，5 秒后自动隐藏 |
| 进度条 | 悬停预览 | 按下拖动，预览气泡在手指上方 |
| 倍速 | 菜单选择 | 底部抽屉选择 |
| 弹幕发送 | 输入框 | 全屏输入浮层（避免键盘遮挡） |
| 上传 | 拖拽 | 系统文件选择器 / 相机 |
| 审核工作台 | 三栏布局 | **不支持移动审核**（信息密度要求高，小屏易误判） |
| 阅读器 | 侧边偏好面板 | 底部抽屉 |

> **明确的产品决策**：审核工作台在移动端只显示只读的队列概览，不提供决策能力。在小屏上审核高风险内容，误判成本远高于"随时能审"的便利。
