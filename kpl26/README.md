> **关于表名**：需求中列举的关键表包含 `Videos`。本设计将其泛化为 `contents` 表，用 `content_type` 枚举区分 `VIDEO` / `AUDIO` / `TEXT` 三类内容——因为平台要求视频、音乐、文本三模态统一管理，审核流程、权限模型、配额机制对三者完全一致，拆成三张表会导致审核逻辑与 RBAC 判定重复三份。类型特有的字段（码率档位、采样率、章节）放入 MongoDB 的 `content_metadata` 集合。

## 全局约束（贯穿所有文档）

| 约束 | 落实方式 |
|---|---|
| 无硬编码密钥 | 所有密钥经环境变量 → KMS/Vault 注入；代码中仅出现 `${VAR}` 占位符 |
| 隐私最小化（GDPR） | 仅采集必要字段；IP 哈希化存储；提供导出与删除接口 |
| 水平扩展 | 应用无状态、会话外置 Redis、任务走 MQ、存储走对象存储 |
| 密码学合规 | 密码 Argon2id、传输 TLS 1.3、管理私钥非对称 + HSM/KMS |
